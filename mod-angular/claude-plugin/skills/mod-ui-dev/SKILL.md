# Working on @mod-internal/ui

The repository has three parts:

| Path | What it is |
| --- | --- |
| `design-system/` | The vanilla HTML/CSS/JS design system. **Source of truth** for markup, class names and CSS; do not change it while porting |
| `mod-angular/projects/ui` | The library: one folder per component in `src/lib/<name>/`, styles in `src/styles/` |
| `mod-angular/projects/demo` | The documentation app: one page per component, plus page templates |
| `mod-angular/tools/` | Generators and checks run by the npm scripts |
| `mod-angular/claude-plugin/` | This plugin. Its references are generated; see "Generated files" |

Run every command from `mod-angular/`.

## Read first

`projects/ui/CONVENTIONS.md` is the porting contract: source files, component rules,
demo page structure. Read it before writing a component or a demo page, and follow it.
`lib/button/` and `pages/button/` are the reference implementations.

The essentials it sets:

- Standalone, OnPush, `ViewEncapsulation.None`, `styleUrl`; signals API only (`input()`,
  `model()`, `output()`, `host` object), `booleanAttribute` for boolean inputs, new control
  flow. Must compile on Angular 20, 21 and 22: stable APIs only.
- The template renders **the same markup and class names** as the design-system page, so
  the copied CSS and the shared `dark-mode.css` keep working. Copy CSS values exactly;
  drop docs-only rules (`.live-demo*`, `.showcase*`, `.props-table*`).
- Form controls implement `ControlValueAccessor` and also expose a `model()`.
- All user-visible text is an input with an English default.
- No new dependencies (no CDK, no Material); SSR-safe (`DOCUMENT`, `DestroyRef`).

## Adding a component

1. Read `design-system/components/<name>/<name>.html`, `.css` and
   `design-system/js/components/<name>.js` (ignore its `*DemoManager`).
2. Create `projects/ui/src/lib/<name>/<name>.ts`, `<name>.css` and `index.ts`, and add
   `export * from './lib/<name>/index';` to `projects/ui/src/public-api.ts`.
3. If the CSS uses the primary greens as a text colour, run `npm run gen:dark-text`.
4. Add the demo page `projects/demo/src/app/pages/<name>/<name>.page.ts` (structure in
   CONVENTIONS.md: content header, `demo-live`, `demo-props`, one `demo-showcase` per
   source section), then `npm run gen:routes`, and add the entry to `DEMO_NAV` in
   `projects/demo/src/app/nav.ts`.
5. Build (`npm run build:ui`) and check the page in the demo (`npm start`) in LTR, RTL and
   dark mode.

## Adding a page template

Page templates are complete screens shown under "Shared page examples" or "Application UI
examples". A template page lives in `pages/<group>/` and has:

- one `<variant>.example.ts` per screen: a standalone component taking a `lang` input
  (`'en' | 'ar'`) with its texts in a `TEXT` object, **and** an exported `<VARIANT>_CODE`
  string constant with the copyable source of the same screen. Keep the two in step. The
  constant may be a template literal, may interpolate other constants, or may call a shared
  builder such as `loginCode({...})` from a sibling file, as long as the builder only
  returns one template literal.
- `<group>.page.ts` with one `<demo-example heading="..." description="..." [code]="...">`
  per variant, where the `[code]` property is assigned directly from the `_CODE` constant.
- an entry in `DEMO_PAGE_EXAMPLES` or `DEMO_APP_EXAMPLES` in `nav.ts`, and a card on the
  matching overview page: `pages/page-examples/page-examples.page.ts` (add the id to
  `ExampleId`, a `@case` preview and an entry in `cards` with the right `count`) or
  `pages/app-examples/app-examples.page.ts` (same pattern).
- then `npm run gen:routes`.

`npm run gen:skill` turns every `demo-example` into a template file of the `mod-ui` skill;
it fails loudly when a `_CODE` constant cannot be evaluated statically, and warns about
constants no page shows.

Email templates are plain functions in `pages/email-templates/<id>.email.ts`, sharing
`email-layout.ts`, and are listed with `this.example('<id>', heading, description)` in
`email-templates.page.ts`.

## Theme and tokens

- Brand colours and the typeface: `projects/ui/src/styles/css/mod-theme.css`.
- `src/styles/mod.css` loads the full vendored theme; `mod-core.css` loads the reduced
  `DGATheme.core.css`, generated by `npm run gen:core-theme` (part of `build:ui`).
- `src/styles/utilities/DGATheme.css` is vendored. It carries two local edits that
  `npm run check:vendor` guards; if you re-sync it from the DGA source, re-apply them.

## Generated files: never edit by hand

| File | Regenerate with |
| --- | --- |
| `projects/demo/src/app/app.routes.ts` | `npm run gen:routes` |
| dark-mode twins in component CSS | `npm run gen:dark-text` |
| `src/styles/utilities/DGATheme.core.css` | `npm run gen:core-theme` |
| `claude-plugin/skills/mod-ui/references/*` except `setup.md` | `npm run gen:skill` (also run by `build:ui`) |
| `claude-plugin/skills/mod-ui-html/references/*` except `setup.md` | `npm run gen:skill-html` (reads `../design-system`) |

`gen:skill` finds templates by scanning every `pages/*/*.page.ts` for `<demo-example>`.
Each one becomes `references/templates/<page folder>--<slug of heading>.md`; the group
heading in `templates.md` is the page's `content-title`, and the `description` attribute
becomes the "What it is" text, so write it to describe the screen.

## Releasing a version

1. Bump `version` in `projects/ui/package.json` (semver: a removed or renamed input is a
   breaking change).
2. `npm run build:ui`, then `npm run pack:ui`: creates
   `dist/ui/mod-internal-ui-<version>.tgz`.
3. Check the build output for budget or compile warnings, and open the demo once.
4. Update the version in the install examples (`README.md`, `projects/ui/README.md`,
   `claude-plugin/skills/mod-ui/references/setup.md`).
5. If the component API, the templates or the skill text changed: update the counts
   written in prose (components in `mod-ui/SKILL.md`, templates in `mod-ui/SKILL.md`,
   `claude-plugin/README.md` and `plugin.json`), bump `version` in
   `claude-plugin/.claude-plugin/plugin.json` so installed plugins update, and rebuild
   the `.skill` files as `claude-plugin/README.md` describes.
6. Hand the `.tgz` to consuming projects (they vendor it and `npm install` the file).

## Demo site

`.github/workflows/build-demo.yml` builds the demo as a downloadable artifact. It runs only
by hand (Actions tab → "Build demo site" → Run workflow) with the base path it will be
served from (default `/mod-library-demo/`). Locally: `npx ng build demo --base-href <path>`;
the output is `dist/demo/browser`. The build needs about 2 GB of free memory because of
the icon stylesheet.

## Before you finish

- `npm run build:ui` passes (it runs the vendor check, core theme and skill generators).
- `npm run build` passes when the demo changed.
- The changed demo page works in English and Arabic, light and dark, desktop and mobile.
- Generated files were regenerated, not hand-edited.
